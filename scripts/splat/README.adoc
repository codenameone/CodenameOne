= Splat

A first-person team paintball shooter and its server, in one Maven project and one
language. Four against four in a self-storage yard or a suburban cul-de-sac, in Team
Paint, Capture the Flag or Hold the Snack Bar, with a grim mission briefing before
every match, a big red PAINTED stamp for every hit, and a referee who catches most
of the players wiping paint off. Around the match is what a live game needs:
accounts, quick matches with bots filling the empty slots, parties with voice chat,
replays, crews, a shop with in-app purchases and rewarded ads, push notifications,
and a console for running the game.

The rules are one module, `rules`, that the app, the server and the tests all
compile. It uses no floating point and no clock, so a match plays out identically
on a phone, on the server and in a replay. The server runs every online match as
the authority and sends snapshots; the app predicts its own player with the same
rules and reconciles when a snapshot arrives, so the marker fires with no wait.

It's a sample of what Codename One does for games, and the project the
Initializr generates when you start from the paintball template.

== The modules

[cols="1,3"]
|===
| Module | What it holds

| `rules` | The deterministic simulation: fields, markers, paintballs, the three
  modes, lag compensation, the bots and replays.
| `shared` | The data transfer objects and `@RestClient` interfaces.
| `common` | The app: the 3D field and HUD, prediction, the menus, the party lobby
  and voice, the replay viewer, the store, the admin console.
| `backend` | The server: accounts, matchmaking, the authoritative match rooms,
  results and replays, moderation, progression, receipts, push.
| `ios` | The iOS build, for generating the Xcode project.
|===

== Running it

Start the server on the development profile. It needs nothing installed: the
database is in memory, purchases and push notifications are simulated, and the
demo accounts `player@`, `rival@`, `trouble@` and `admin@splat.example` exist,
each with the password `splat-demo`.

[source,bash]
----
CN1_PROFILE=dev backend/server.sh run
----

Then run the app in the simulator:

[source,bash]
----
mvn verify -Psimulator -DskipTests -Dcodename1.platform=javase
----

The app looks for the server at `http://localhost:8080/`; *Settings* changes it.
`backend/server.sh run --port N` serves on another port.

For the native iOS app, generate the Xcode project on a Mac, open it and run it
from Xcode:

[source,bash]
----
mvn package -DskipTests -Dcodename1.platform=ios -Dcodename1.buildTarget=ios-source -Dopen=false
----

== Tests

[source,bash]
----
mvn -pl rules test   # <1>
mvn -pl rules,shared,backend -Dcodename1.platform=backend test   # <2>
./run-e2e.sh   # <3>
./check-template.sh   # <4>
----
<1> Determinism: the same seed and inputs give the same match, and the golden
    replays still end the way they were recorded.
<2> The server's tests: whole matches over its rooms and sockets, replays of
    their results, input floods and aimbot flags, receipts, progression and
    moderation.
<3> Starts the server on the `test` profile and runs the app's tests against it
    in the simulator. The screenshots the developer guide shows land in
    `target/e2e-shots`.
<4> Generates a project from the Initializr template, under another name and
    package, and builds it.

`.github/workflows/splat.yml` runs them, and builds the app for Android and
iOS.

== The Initializr template

`scripts/sync-initializr-template.py splat --write` copies this project into the
Initializr's resources; without `--write` it fails when they differ, which is what
CI runs. Change the project here, never the copies.
